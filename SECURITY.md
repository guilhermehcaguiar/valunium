# Segurança

Projeto em desenvolvimento. **Não publique vulnerabilidades sensíveis, tokens ou dados privados em issues públicas.** Use um mecanismo privado de reporte quando configurado pelos mantenedores (por exemplo, GitHub Private Vulnerability Reporting). Nenhum e-mail de segurança foi anunciado.

Até existir um canal privado, não envie detalhes exploráveis para uma issue pública. Não compartilhe credenciais.

Política crítica: o projeto apenas acompanha informações financeiras e **jamais** realiza ordens, transferências ou execução financeira. Relate qualquer implementação que viole isso.
